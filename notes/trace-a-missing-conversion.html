How to trace a missing conversion from click to report

FroggyAds Insights

Start with one controlled conversion when a campaign report is missing an event you expected. A total can tell you that two systems disagree. A single event can show exactly where they started to disagree. Record the click time, the action time and the reporting time zone, then keep that case separate from routine traffic while you investigate.

Follow the identifier through the visit

Capture the click identifier at the first point you control and check that the same value is available when the test action completes. Redirects, consent choices and a change of domain can each affect which values survive the visit. Record the first and last observed values and compare them before you change any settings. The conversion tracking guide describes the other evidence to retain, including the event definition and the record used to detect duplicates.

Separate delivery from acceptance

If the test produces a server callback, find the request and its response in your logs. Record the time and outcome, then look for a corresponding accepted event. A successful response shows that the receiver handled the request at the transport layer. The reporting system may still reject the event, ignore a duplicate or keep it outside an attribution window. The postback tracking guide explains how to preserve an event identifier through retries and check the downstream result.

Use a redacted reference in your investigation notes. Keep callback secrets, personal data and complete live URLs out of the shared case. If you replay the test, follow the documented retry behavior and verify that the same business event appears only once.

Check the report on the same terms

Once you have an accepted event, compare the report with the same time zone, campaign filter and outcome definition. An event counted on its conversion date can sit in a different row from a report grouped by click date. Approval and processing delays can move the apparent gap again. The campaign reporting guide explains how to compare source-level results with records from the tracker or the business.

  • If the identifier disappears before the action, investigate the handoff that last held the original value.
  • If the callback arrives without an accepted event, inspect the recorded outcome and deduplication history.
  • If the event is accepted but absent from the report, compare date windows, filters and the event's reporting eligibility.

Keep the first confirmed break and the evidence that supports it. Fix that handoff, then repeat the same controlled case and compare the new result before making a campaign decision.
